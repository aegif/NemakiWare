### Phase 1 — R260（`$expand=children`。測定 1〜2 時間 + バッチ半日）

**1-0 原因の測定（製品は変えない）— 2026-11-11 に測った。** `CmisEntityProcessor.expandChildren` は
`navigationService.getChildren` の 12 番目の引数（フォルダ自身を返す holder）に null を渡していた。配備中の WAR のクラスを
単独で呼ぶと、holder が null のとき `NavigationServiceImpl.getChildren` は 122 行目（`parentObjectData.setValue`）で
`NullPointerException` を投げ、holder を渡すとその行を通る。`expandChildren` の全体が `catch (Exception e) { }` なので、
例外は握り潰され、`Link` が足されず、serializer が `children: []` を書いていた。

nb33 で `$expand` の形を 38 通り測った（直す前、再起動をはさんで同じ答え）。壊れていたのは `children` だけではない。
- 正しく答える: `Folders(F)?$expand=parent`、`Documents(D)?$expand=parents`、`Relationships(R)?$expand=source,target`。
- 誤った答え: `children` は子が 3 件でも 101 件でも 0 件。`$expand=*` と `Documents(D)?$expand=parent` は、在る親を `null`。
  `children($top=1)`・`parent($levels=2)` などは、項の option を黙って落とす。
