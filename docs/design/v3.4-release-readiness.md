## 5. Playwright の失敗の内訳 — 全件、退行でないと確かめた

| 実行 | 結果 |
|---|---|
| R51 前 | 910 passed 相当 / **8 failed** / 3 flaky |
| R51 後 | **910 passed / 7 failed / 3 flaky** |

- **1 件は本物の製品欠陥だった** → R51 として処置済み（`Archive Management API ›
  should list archives`）。R51 後の実行で**消えている**。
- **3 件はデータ不足**: プレビューの 3 本が探す `PDFサンプル.pdf` / `画像サンプル.png` /
  `テキストサンプル.txt` が、確認した範囲（ルート直下 100 件）に無い。
- **4 件は退行ではない（実測で確定）**: グループ管理 2・管理者権限 1・ACL 継承 1。
  - 単独で走らせ直しても**同じ 4 件が落ちる**（timing ではない）。
  - **master を worktree でビルドして同じ環境にデプロイし、同じ 4 spec を走らせたところ、
    落ちた 4 件・flaky の 3 件・通った 13 件・所要 23.5 分まで完全に一致した。**
  - 3.4 は `AclServiceImpl` と `UserGroupDaoDelegate` を触っているので「領域が無関係だから
    退行ではない」とは言えず、この突き合わせが唯一の確かめ方だった。
- flaky 3 件（グループ作成・管理者権限の付与/剥奪）は master でも同じく flaky。
