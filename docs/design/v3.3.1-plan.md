# v3.3.1 計画 — 3.3.0 の残件パッチ

2026-08-17 起案。3.3.0 リリース時に「分かっていて見送った」項目のうち、**破壊的変更を
伴わないもの**を 3.3.1 として閉じる。破壊的なものはここに入れない
([`authenticity-roadmap.md`](authenticity-roadmap.md) §2 に移管)。

出典: [`v3.3-release-blockers.md`](v3.3-release-blockers.md) §8 の follow-up 節。
**着手前に必ずコードで再確認すること** (台帳の文言を正として着手しない — 3.3 で
T1 の「未修正」記述が実際には修正済みだった前例がある)。

## 判定基準

- 3.3.0 と同じ観測可能な挙動を保つ (不具合修正を除く)
- RELEASE_NOTES に「破壊的変更」節が**増えない**こと
- 各修正は判別するテストを伴う (負のコントロール: 修正を戻すと落ちること)

## 項目

| # | 何を | 直し方の方針 | 検証 |
|---|---|---|---|
| 1 | **testuser patch「有効時」の失敗の焼き付き** — `Patch_TestUserInitialization` の catch 4 箇所が例外を握り潰して正常復帰するため、有効化して seed に失敗しても `PatchHistory` が記録され再試行されない | catch を throw 化し、基底の per-repo catch (履歴を記録せず `allSucceeded=false`) に任せる。既存テストのモック (null 返し) を実オブジェクト返しに組み直す | 「seed 失敗 → 履歴なし → 次回起動で再試行」をテストで固定 |
| 2 | **`StartupProbeService` の probe 非原子性** — `currentState` と `lastProbedVersion` が別々の `AtomicReference` で、並行 reprobe 時に「同じプローブの結果」という保証が無い | `(state, version)` を 1 つの record にして 1 個の `AtomicReference` で差し替え | 既存の gate テスト群が回帰を捕まえる。競合そのものの再現は不要 (fail-closed 方向のずれのみ) |
| 3 | **Setup Mode 補助エンドポイントが version gate の外** — `/setup/auth/apply` と `/setup/admin/change-password` は CouchDB 3.3 未満にも書ける | `couchDbVersionRefusal` を両エンドポイント冒頭に足す (パターン確立済み: `SetupApplyResource`) | `/apply` と同型のテスト + 負のコントロール |
| 4 | **security-scan の検知漏れ** — `key = value` (空白) 記法と、検査対象ファイルの消失を検知できない | 正規表現を `key\s*=` に広げ、対象ファイルの存在チェックを先頭に足す | v3.2.8 のファイルに対して依然 hit すること・現ツリーで 0 hit を確認 |
| 5 | **CodeQL アラート 23 件の個別 dismiss** — triage 済み (blocker 0、台帳に記録) だが、アラートは open のまま。放置すると次の PR で再びゲートが赤くなる | 各アラートを理由付きで dismiss (`sensitive-log` の誤検知は "false positive"、MD5 は "won't fix — documented legacy path")。`sensitive-log` が多発するならクエリ設定で調整 | dismiss 後、doc-only PR でアラートゲートが緑になること |
| 6 | **dev 依存の npm audit high 3 件** (nanoid / postcss 系) — 出荷物と CI ゲート (`--omit=dev`) には乗らないが、`npm audit` 素通しでは見える | ビルドツールチェーンの bump。`npm run build` + UI 単体 191 件で回帰確認 | `npm audit` (dev 込み) 0 件 |
| 7 | **SOAP 実測の拡張** — 3.3.0 で実往復させたのは RepositoryService 1 本のみ | ObjectService (`getObjectByPath /`) と NavigationService (`getChildren`) の 2 往復をスモークに追加。WS **クライアント** binding の製品内利用箇所の有無を調査して記録 | 3 サービスの実応答 |
| 8 | **Swagger UI「Try it out」実行系** — 描画は確認済み、UI からのリクエスト発火が未実測 | ブラウザで GET 系 1 本 (Get ACL 等) を Execute し、認証ヘッダ/CSRF が UI 経由で通ることを確認。可能なら Playwright 1 本に固定 | 実行結果 200 の目視 + テスト |
| 9 | **Playwright CI の 3h タイムアウト連鎖** — 既知 flake (master 系でも 13 回中 10 回失敗)。落ちるにしても 3 時間は長すぎる | まず `timeout-minutes` をジョブに設定して fail-fast 化。その上でシャーディング (`--shard`) と cleanup の `page.goto` リトライを検討。**flake の根治はスコープ外** (症状は記録済みの client-side metadata-XHR hang) | CI 所要時間の上限が効くこと |
| 10 | **文書の呼称統一** — `v3.3-release-plan.md` が再索引劣化を旧称 R1 で呼ぶ箇所が残る (現行 RX1) | 機械置換 + 前後確認 | grep で R1 系呼称 0 件 |

## やらないこと (3.3.1 でも)

- 破壊的変更はすべて [`authenticity-roadmap.md`](authenticity-roadmap.md) §2 へ
  (DAO の fail-fast 化、残り 17 パッチの throw 化、B1-a / T2 / V2 / V5 / RX1、
  既定値の変更類)
- `lib/built-jars` の 1.1.0 jar と `install-opencmis-local.sh` の削除
  (過去タグのビルドが壊れる。非推奨警告は 3.3.0 で追加済み)
- AGENTS.md 歴史節の全面書き直し (履歴バナーで足りている)

## 運用メモ (コード外)

- 常設デモ **avenue.aegif.jp** の 3.3.0 更新は 3.3.1 を待たない。実施時は
  **全再索引 + 初期 epoch stamp が必須** ([`../operations/v3.3.0-upgrade-runbook.md`](../operations/v3.3.0-upgrade-runbook.md))。
  既存 Solr ボリュームを引き継ぐ場合は O0.5 (schema 3 フィールド) を忘れないこと。
