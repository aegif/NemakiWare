### 1-B. R146 — incident のログの深い入れ子（バッチ 2 で処置 — 正典 R146）

`Secrets.loggable` は suppressed の throwable を再帰で作り直すので、suppressed が数千段に入れ子になると
`StackOverflowError` になる。incident の行と所定の応答が出ずに汎用の 500 になり、execute では適用済みの行の
監査（`PRINCIPAL_BATCH`）も書かれない（正典 R146）。

正典は同じ行に 2 つ添えている — 錠 `aSuppressedFailureIsLoggedRedacted` が最上位の suppressed しか測らない
（各 node の suppressed と、suppressed の cause の鎖を見分けない）こと、同じ throwable が cause と suppressed の
2 か所にあると primary の cause の鎖が印なしに切れること。

直し方: 作り直しを反復にして、primary の cause の鎖を先に辿る。入れ子の段数と数の両方に上限を置く（上限を
超えた分は「省いた」と書き、黙って落とさない。logback の `ThrowableProxy` も 1 段ごとに再帰するので、上限は
logger に渡す写しにも効く）。2 か所に現れる throwable は 2 度目を印で置き換える。
錠: 深い suppressed の入れ子で incident の行・所定の応答・適用済みの行の監査が出ること、深い cause の鎖・浅くて広い
suppressed・同じ throwable の繰り返しでも写しが 64 個で止まり、止めたと書くこと、各 node の suppressed と suppressed の
cause の鎖も伏せること、primary の cause の鎖が切れないこと、輪になった鎖を印つきで切ること。

### 1-D. R115 — 組み込みのアカウントと自分自身の guard を正準の入口へ（バッチ 4 で処置 — 正典 R115）

一括プリンシパル是正（C-1）の `forbidden`（組み込みの admin・サービスアカウントの削除と admin の剥奪、
実行者自身の削除と admin の剥奪）は一括の入口だけを守る。既存の 3 つの入口（legacy `/rest` の
`UserItemResource`、Spring MVC の `UserController`、Jersey の `UserResource`）には同じ guard が無く、
`admin` を 1 件ずつ消せる（正典 R115）。

直し方（バッチ 4 で設計を詰める）: 判定を 1 か所にまとめ、3 つの入口と一括の入口が同じ判定を通る。
組み込みのアカウントの削除は実行者に関わらず `ContentServiceImpl.deleteUser` でも拒む。ディレクトリ同期
（`DirectorySyncServiceImpl`）が組み込みのアカウントを消さないことも確かめる。CMIS の `deleteObject` で
`nemaki:user` の item を消す経路（`ObjectServiceInternalImpl` → `ContentServiceImpl.delete`）は `deleteUser` を
通らなかった — 2026-10-09 に nb33 で、admin がテスト用の利用者を Browser binding の削除で消せることを実測した。
バッチ 4 の 1 巡目で、この経路と Microsoft のクラウド同期の削除を正準の `deleteUser` に回した。
2 巡目で CMIS の経路をさらに直した — 判定を parentChild の cascade の前に問う、呼び出し元の context で書く
（3.4.0 と同じく変更ログ・webhook・archive に実行者が残る）、頼まれた文書だけを消し、userId が別の文書に
解決されるときは拒む、Jersey の `/items/{id}`・`/objects/{id}` が拒否を 403・422 で返す。CI の unit の一覧に
3.4.1 の製品の錠（R146・R125・R115）を足した。3 巡目で、userId の解決を cascade の前の 1 回だけにし（削除の時に
問い直すと、その間に作られた利用者で cascade の後に拒否になる）、重複についての記述をコードに合わせた（重複その
ものは検出しない — 同じ領域の P2 が 2 巡続いたので、検出は足さずに記録して止めた）。4 巡目で、削除の時の保護の
判定の問い直しも同じ形（Solr の利用者 id を `nemaki_conf` から読み直す）だと分かり、判定は cascade の前に 1 回だけ
下してその結果を削除に渡す形にした。
錠: 入口ごとに、組み込みの admin・サービスアカウント（Solr・mcp-service）と実行者自身の削除・admin の剥奪が
拒まれること。

### 1-J. R156・R157・R158 — 書き直しで失う人、検索の外の DN が名指しうる照会済みの利用者、止めと残す規則に残る形（バッチ 14 — 2026-10-14、オーナーが「もう 1 バッチ開けて直す」を選んだ）
