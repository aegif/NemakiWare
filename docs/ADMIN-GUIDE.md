## 2. ユーザー管理

### ユーザーの作成

1. 「管理」→「ユーザー管理」を開く
2. 「新規ユーザー」をクリック
3. 以下の情報を入力:
   - ユーザーID（ログインに使用）
   - 表示名
   - パスワード（BCrypt でハッシュ化されて保存）
   - メールアドレス（任意）
   - 管理者権限（チェックボックス）
4. 「作成」をクリック

### ユーザーの編集

ユーザー一覧から対象ユーザーをクリックし、「編集」で情報を変更できます。

### パスワードリセット

管理者は任意のユーザーのパスワードを変更できます（旧パスワードの入力不要）。

### ユーザーの削除

ユーザー一覧から「削除」をクリック。削除されたユーザーはログインできなくなりますが、過去の操作ログは残ります。

## 3. グループ管理

### グループの作成

1. 「管理」→「グループ管理」を開く
2. 「新規グループ」をクリック
3. グループ ID と表示名を入力
4. 「作成」をクリック

### メンバー管理

1. グループ一覧から対象グループをクリック
2. 「メンバー」タブでユーザーまたはサブグループを追加・削除

### グループ階層

グループは親子関係を持てます。子グループのメンバーは親グループの権限を継承します。

---

## 4. タイプ管理

CMIS のオブジェクトタイプを管理します。

### 基本タイプ

| タイプ | 説明 |
|--------|------|
| `cmis:document` | ドキュメント（ファイル） |
| `cmis:folder` | フォルダ |
| `cmis:relationship` | リレーションシップ |
| `cmis:policy` | ポリシー |
| `cmis:item` | アイテム |

### カスタムタイプの作成

1. 「管理」→「タイプ管理」を開く
2. 「新規タイプ」をクリック
3. タイプ ID、表示名、親タイプを設定
4. カスタムプロパティを追加:
   - プロパティ名、データ型（文字列/数値/日付/真偽値）
   - 必須/任意、検索可能/不可
5. 「作成」をクリック

### タイプ定義の編集

JSON エディタでタイプ定義を直接編集できます。型定義のインポート/エクスポートも可能です。

### GUI タイプエディタ

ビジュアルエディタでプロパティの追加・削除・並び替えが可能です。

## 5. 権限（ACL）管理

### フォルダ/ドキュメントの権限設定

1. ドキュメント一覧で対象を選択
2. 「権限」ボタンをクリック
3. 権限管理画面で:
   - ユーザーまたはグループを追加
   - 権限レベル（`cmis:read` / `cmis:write` / `cmis:all`）を設定
4. 「保存」をクリック

### 権限の継承

- デフォルトでは親フォルダの権限を継承
- 「継承を解除」で独自の権限に切り替え
- 継承解除時、親の ACE が直接 ACE としてコピーされます

### 特殊プリンシパル

| プリンシパル | 説明 |
|-------------|------|
| `GROUP_EVERYONE` | 全ユーザー |
| `cmis:anyone` | 匿名アクセス含む |

## 6. アーカイブ管理

削除されたドキュメントの管理と復元。

### アーカイブ一覧

1. 「管理」→「アーカイブ管理」を開く
2. 削除されたドキュメントの一覧が表示されます
3. 検索ボックスでフィルタ可能

### 復元

1. 復元したいドキュメントを選択
2. 「復元」をクリック
3. 元のフォルダに復元されます

### 完全削除

1. 対象を選択して「完全削除」をクリック
2. 完全削除するとデータベースから物理削除され、復元できなくなります

### 一括操作

チェックボックスで複数選択し、一括復元・一括削除が可能です。

## 7. 検索エンジン（Solr）管理

### インデックスの再構築

1. 「管理」→「Solr 管理」を開く
2. 「フルインデックス再構築」をクリック
3. 進捗バーが表示されます（大量ドキュメントでは数分〜数十分）

### RAG ベクトルインデックス再構築

RAG（セマンティック検索）が有効な場合:

1. 「RAG インデックス再構築」をクリック
2. 全ドキュメントの embedding が再計算されます

### ステータス確認

- インデックス対象ドキュメント数
- 最終インデックス日時
- Solr コア状態

## 8. Webhook 管理

ドキュメントの作成・更新・削除時に外部 URL に通知を送信します。

### Webhook の作成

1. 「管理」→「Webhook 管理」を開く
2. 「新規 Webhook」をクリック
3. 設定項目:
   - URL（通知先）
   - イベント（作成/更新/削除/全て）
   - 対象フォルダ（特定フォルダ以下のみ）
   - 有効/無効
4. 「保存」をクリック

### バッチ配信

子ドキュメントの一括操作時は `CHILD_BATCH` イベントとしてまとめて配信されます。

## 9. クラウドディレクトリ同期

Google Workspace / Microsoft Entra ID のユーザー・グループを NemakiWare に同期します。

### 設定

1. 「管理」→「クラウドディレクトリ同期」を開く
2. プロバイダ（Google / Microsoft）を選択
3. API 認証情報を設定
4. 同期対象のフィルタを設定

### 手動同期

「同期実行」をクリックすると即時同期が開始されます。

### 自動同期

定期同期を有効にすると、設定間隔で自動同期されます。

## 10. 外部インジェスト管理

外部システムからドキュメントを自動取り込みする機能です。

### コネクタ管理

1. 「管理」→「統合設定」→「コネクタ管理」タブ
2. 対応アダプタ:

| アダプタ | 対象 |
|----------|------|
| IMAP | メールサーバー |
| Gmail | Gmail API |
| M365 Mail | Microsoft 365 メール |
| Slack | チャンネルメッセージ |
| Teams | チャンネルメッセージ |
| Mattermost | チャンネルメッセージ |
| Chatwork | ルームメッセージ |
| Notion | ページ・データベース |
| Salesforce | レコード |
| Box | ファイル |
| Dropbox | ファイル |

3. コネクタごとに認証情報、エンドポイント、レート制限を設定

### インポートプロファイル

1. 「インポートプロファイル管理」タブ
2. プロファイルにはデータ重複制御ポリシーを設定:
   - `skip_if_same_version` — 既存と同じなら無視
   - `create_new_version` — 新バージョンを作成
   - `replace` — 既存を上書き

### 手動インポート

1. 「手動インポート」タブ
2. プロファイルとコネクタを選択
3. ファイルをアップロード
4. 結果（成功/スキップ/エラー）が表示されます

### スケジューラ

1. 「スケジューラステータス」タブ
2. 定期ポーリングの状態確認
3. 手動トリガー実行

### ジョブ履歴

1. 「ジョブ履歴」タブ
2. 過去の取り込みジョブの結果一覧
3. ステータス: `COMPLETED` / `PARTIAL` / `FAILED` / `STUCK`

### デッドレターキュー（DLQ）

取り込み失敗したアイテムの管理:

1. 「DLQ」タブで失敗エントリを確認
2. エラー内容を確認（`[transient]` / `[permanent]`）
3. 「リトライ」で再取り込み（60秒のクールダウンあり）
4. 成功すると自動的に DLQ から削除されます

## 13. 設定ビューア

システム設定の現在値と設定元を確認できます。

1. 「管理」→「設定ビューア」を開く
2. 各設定項目のソースが表示されます:

## 15. インポート / エクスポート

ドキュメントの一括インポート/エクスポートを行います。

### エクスポート

1. 「管理」→「インポート/エクスポート」を開く
2. エクスポート対象のフォルダを選択
3. 「エクスポート」をクリック
4. ZIP ファイルがダウンロードされます（メタデータ + コンテンツ）

### インポート

1. エクスポートした ZIP ファイルを選択
2. インポート先フォルダを選択
3. 同名ファイルの上書き設定
4. 「インポート」をクリック

## 17. API ドキュメント

1. 「管理」→「API ドキュメント」を開く
2. Swagger UI でREST API の一覧と試行が可能

### CMIS API

- AtomPub Binding: `/core/atom/{repositoryId}`
- Browser Binding: `/core/browser/{repositoryId}`

### REST API

- `/core/rest/repo/{repositoryId}/...` — レガシー REST
- `/core/api/v1/...` — Spring MVC API

> REST API の POST/PUT/DELETE は CSRF 保護されています（Jersey `/core/rest/` と Spring MVC `/core/api/v1/` の両方）。
> CLI/curl からは以下のいずれかのヘッダーで CSRF バイパスできます:
> - `X-Requested-With: XMLHttpRequest`
> - `Authorization: Bearer <token>` (非 Basic)
> - `AUTH_TOKEN: <token>` / `X-API-Key: <key>`
>
> **Basic 認証のみの場合は `X-Requested-With` が必須です**（ブラウザが自動付与する ambient credential のため）。
> 詳細: [CLAUDE.md の CSRF セクション](../CLAUDE.md#csrf保護-rest-api)

### MCP (Model Context Protocol)

Claude Code 等の AI ツールからリポジトリを操作できます。

詳細: [MCP-SERVER.md](MCP-SERVER.md)
